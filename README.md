# 界限 · JieXian

一个原生 Android 应用限制工具：给应用设置每日使用额度，或每天指定一段不可使用的时间。界面使用 Kotlin + Jetpack Compose + Material 3，所有数据仅保存在本机。

## 核心行为

- **每日限额**：按系统 `UsageEvents` 活动事件累计每个应用的前台时长，达到额度后本次限制持续到次日 00:00；首页会显示已计入的时长，便于核对。
- **强制模式（可选）**：把界限设为设备管理员（Device Owner）后，额度用尽或进入禁用时段时由系统暂停对应应用，应用无法启动，清理后台、重启手机都无法绕过；解除该模式需要恢复出厂或一条 adb 命令。未开启时只能依赖无障碍服务，系统「强行停止」或深度清理仍可绕过。
- **组合额度**：每日限额规则可选设置「这组应用合计上限」，组内所有应用的前台时长合计达到上限后，整组应用一起锁定到次日 00:00；单个应用未用满自己的额度也会被一起限制。
- **禁用时段**：例如每天 23:00 至次日 09:00，支持跨午夜；开始时间包含在内，结束时间不包含。
- **允许清单**：禁用时段的反向规则，时段内只有勾选的应用可以使用，其余可启动应用会回到桌面；桌面、系统界面、输入法、权限弹窗、系统设置和厂商安全中心等必需界面不会被限制。
- **规则可增删改**：后续周期使用最新规则。
- **本次限制不可解除**：一旦超额或进入禁用时段，会单独持久化一条锁定快照。修改或删除来源规则不会删除、缩短或延长这张快照，也没有加时入口。
- **先锁定，再打开**：当前禁用时段内保存规则时会立即生成本次锁定；后台守护服务也会周期检查，不依赖受限 App 先被打开。
- **多种限制可叠加**：同一应用可同时有每日限额和禁用时段，拦截以仍未结束的锁定为准。
- **单 App 额度提醒**：每个应用今日额度剩余约 5 分钟时，发送一次系统通知。
- **禁用开始提醒**：每个禁用时段开始前 5 分钟，发送一次系统通知；跨午夜周期同样适用。
- **今日亮屏提醒**：按系统亮屏/熄屏事件累计整机亮屏时长，每满 1 小时提醒一次；熄屏播放音乐或听书不计入。
- **后台常驻**：无障碍服务连接后启动低优先级前台服务与常驻通知，从多任务划掉界限后进程仍然存活，拦截不会随任务一起消失。
- **被谁停掉、怎么恢复**：从多任务划掉或普通进程清理，系统会自动重新绑定无障碍服务，不需要重新授权；只有系统「强行停止」或厂商深度清理才会清空无障碍授权（Android 的安全设计，应用无法自行重新开启），此时首页会提示只差这一项，重新开启后守护自动恢复。
- **自愈与状态可见**：开机、应用更新后自动恢复守护；15 分钟看门狗检查一次；无障碍服务用心跳标记存活，首页和常驻通知会区分「运行中」与「已被系统停止」。
- **守护记录**：本机保存最近 40 条守护状态变化（无障碍授权是否仍在、服务连接/解绑、常驻服务启停、自愈唤醒、每次打开应用时的状态快照），可在「后台守护 → 守护记录」或「守护已停止 → 诊断」查看，用来判断是系统清除了授权，还是只是进程被杀。
- **后台运行引导**：首页提供忽略电池优化、厂商自启动设置入口，并说明被系统清理后的恢复方式。

## 界面

- 静夜深绿、月光渐变与半透明卡片，圆角控件与明确的锁定状态。
- 首页显示规则、今日用量、额度进度、本次解锁时间和权限状态。
- 应用选择器支持搜索并显示真实应用图标。
- 每日额度支持滑杆及 15 / 30 / 60 / 90 / 120 分钟快捷选项，范围为 5–720 分钟。
- 时段选择支持系统 24 小时时间选择器及跨午夜预览。
- 独立拦截页只提供返回桌面与调整后续规则，不提供临时加时。

## 构建

要求：

- JDK 17
- Android SDK 35
- 最低运行系统 Android 8.0（API 26）

```bash
cd JieXian
export JAVA_HOME=/path/to/jdk-17
./gradlew :app:assembleDebug :app:testDebugUnitTest
```

本机使用的 JDK 路径为：

```bash
export JAVA_HOME=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home
```

生成的 APK：

```text
app/build/outputs/apk/debug/app-debug.apk
```

安装到已连接设备：

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

也可以直接用 Android Studio 打开本目录并运行 `app`。

## 自动发布与应用内更新

源码和公开发布仓库：<https://github.com/honey2306/JieXian>

- 推送到 `main` 或提交 Pull Request 时，GitHub Actions 自动构建 Debug APK，并运行测试和 Lint。
- 推送 `v1.1.0` 这类版本标签时，Actions 使用加密 Secrets 中的正式 JKS 签名，生成单调递增的 `versionCode`、Release APK 和 `update.json`，并发布到 GitHub Releases。
- App 启动及守护服务后台每 6 小时检查一次公开更新清单；也可点击首页右上角的更新图标手动检查。
- 发现新版本后显示静夜风格更新卡片和系统通知。点击“下载并安装”后，下载 APK、核对文件大小和 SHA-256，再交给 Android 系统安装界面确认。
- 首次更新需要允许“安装未知应用”。普通 App 不能静默安装；用户始终可以在系统界面取消。
- 更新仅支持同一正式签名且 `versionCode` 更高的版本。Debug 签名安装包不能直接覆盖正式版。

正式签名保存在开发机的 `~/.jiexian/`，仓库忽略 `keystore.properties` 和 JKS 文件。GitHub Secrets 使用 `KEYSTORE_BASE64`、`KEYSTORE_PASSWORD`、`KEY_ALIAS`、`KEY_PASSWORD`。

## 首次使用需要授权

1. **使用情况访问**：用于读取本机前台使用时长，计算每日额度。
2. **无障碍服务「界限 · 应用守护」**：用于获得应用窗口包名，在受限应用进入前台时执行返回桌面并打开拦截页，并在后台检查到期提醒。
3. **系统通知**：用于发送单 App 额度、禁用开始和今日亮屏时长提醒，并显示守护状态常驻通知。Android 13 及以上首次启动会请求运行时通知权限；拒绝后也可从首页权限卡进入系统设置开启。
4. **后台运行**：建议在首页「后台守护」中忽略电池优化；小米、华为、OPPO、vivo 等系统还需要在自启动管理中允许界限。

授予无障碍服务后，常驻通知会显示「守护运行中」。如果从多任务清掉应用后通知变成「守护已停止」，点通知里的「重新开启」或回到首页重新开启无障碍服务即可恢复。

首页会显示缺失的权限并跳转到对应系统设置。授权完成后返回应用即可。

部分 Android 版本对侧载应用启用无障碍服务有额外限制，需要先在系统“应用信息 → 更多 → 允许受限制的设置”中允许，再开启服务。不同厂商设置名称可能不同。

上架应用商店时，常驻前台服务与「忽略电池优化」请求可能需要按平台政策额外说明；本项目通过 GitHub Release 分发。后台保活相关的 `FOREGROUND_SERVICE*`、`RECEIVE_BOOT_COMPLETED`、`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` 权限都只用于守护服务自身。

## 隐私

- 更新功能声明 `INTERNET` 和 `REQUEST_INSTALL_PACKAGES`，仅连接 GitHub 公开 Release 获取更新清单与 APK，不上传规则、使用统计或其他个人数据。
- 规则与锁定快照保存在 Room 私有数据库中。
- 使用统计与亮屏/熄屏事件仅通过 Android `UsageStatsManager` 在本机查询；不读取音频内容或播放状态。
- 提醒去重记录保存在本机 `SharedPreferences`，不包含通知正文或使用明细。
- 无障碍配置允许系统提供窗口事件，但代码只读取事件包名，不遍历视图、不读取文字、不截取屏幕。

应用列表通过精确匹配 `MAIN + LAUNCHER` 的 `<queries>` 声明获取，没有请求读取全部已安装应用的 `QUERY_ALL_PACKAGES` 权限。若上架应用商店，仍需要按平台政策说明使用情况访问和无障碍 API 的核心用途；这不代表已经获得商店审核豁免。

## 代码结构

```text
app/src/main/java/com/jiexian/app/
├── data/                 # Room、应用列表、UsageStats 查询
├── domain/               # 规则计算、提醒判断与亮屏事件计算
├── model/                # AppRule 与独立的 ActiveLock 快照
├── service/
│   ├── LimitAccessibilityService.kt  # 前台检测与拦截
│   ├── GuardService.kt               # 前台常驻服务与守护状态通知
│   ├── GuardianHeartbeat.kt          # 无障碍服务存活心跳
│   ├── GuardianScheduler.kt          # 开机/看门狗重启与后台运行保护
│   ├── GuardianRestartReceiver.kt    # 开机、更新后的恢复广播
│   ├── GuardScopeProvider.kt         # 允许清单可限制的应用范围
│   ├── LockSnapshotter.kt            # 周期物化当前限制
│   └── ReminderScheduler.kt          # 收集数据并调度系统提醒
├── notifications/        # 提醒渠道、权限检查与状态栏通知
├── update/               # 更新检查、校验、下载和系统安装会话
├── ui/                   # 首页、编辑器、拦截页、ViewModel
└── util/                 # 权限与时间格式工具
```

关键设计：`app_rules` 与 `active_locks` 没有外键级联。删除规则只影响后续周期；锁定快照有自己的解锁时间。保存规则时会立即物化当前限制，服务每 5 秒补查周期变化。前台拦截同时监听无障碍窗口事件和 `UsageStatsManager` 的 Activity 恢复事件，后者覆盖部分桌面从多任务恢复时不发送预期无障碍事件的路径，并用事件时间戳避免旧记录误拦截。

## Android 系统边界

这是普通可安装 App，不是系统级管控。前台服务、开机广播和看门狗只能对抗普通的多任务清理和系统回收，无法阻止用户主动「强行停止」、关闭无障碍、清除应用数据、卸载应用、恢复出厂或修改系统时间。强行停止还会取消所有闹钟，直到再次打开应用。

允许清单模式下，系统仍会保留桌面、系统界面、输入法、权限弹窗、系统设置、厂商安全中心和「界限」自身，以免设备无法操作或无法恢复授权。

若要求设备所有者也无法绕过的企业/家长管控，需要额外实现 Device Owner / Device Admin 策略，并在设备初始化或受管配置阶段完成授权；本版本没有宣称具备该能力。
